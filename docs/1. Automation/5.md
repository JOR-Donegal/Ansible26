# Data Models

Behind any configuration initiative, we need a data model. Some questions arise when we are modelling a system 

- What is its configuration? 
- If we can retrieve data from the system, what is its state? 
- Can the equipment notify us of events which occur? 

## XML

Where data must be human and machine readable, most modern systems will use _Extensible Markup Language_ (XML).

````xml
<?xml version="1.0"?>
 <note> 
    <to>Class</to>
    <from>JOR</from>
    <duedate>18MAR23</duedate>
    <heading>Assignment</heading>
    <body>Assignment 1 has now been posted to the web. </body>
</note>

````

An XML document consists of

- A declaration of XML version
- A root element within which all other elements must be nested
- Child elements (to, from, duedate, heading, body)
- End of root element

All elements must have a closing tag, normally marked as __/__

Every element can be nested, and this nesting provides unique paths to elements, some of which may otherwise have the same name. This gives each element namespace isolation.

Attributes can be contained in the start tag of an element and must be contained in quotation marks, for example

````xml
<note date=”18MAR23”>.
````

Generally, I prefer to use elements rather than attributes.

## JSON

JavaScript Object Notation or JSON is a good alternative as an underlying data standard. XML is a bit verbose, but well structured. JSON is more economical and easier for a human to read.

````json
{ 
"name":"John", 
“job”: “Lecturer
"age":”Too old”, 
“pay":"Too little" 
}';
````

You should review the basics of [JSON](https://www.w3schools.com/js/js_json.asp)

## YAML

YAML (YAML Ain't Markup Language) is minimalist compared to XML and is used by some automation tools, notably Ansible.

````yaml
# Lecturers

JOR:
	FirstName: John
	Surname: ORaw
	Job: Lecturer
	        Brain Surgeon
	        Rocket Scientist

````

You should also review the basics of [YAML](https://docs.ansible.com/projects/ansible/devel/reference_appendices/YAMLSyntax.html)
